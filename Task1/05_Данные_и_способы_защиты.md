# Данные для защиты и способы защиты

## 1. Назначение

Документ определяет, какие данные подлежат защите и каким способом. Опирается на классификацию из `01_Инвентаризация_конфиденциальных_данных.md` и проблемные зоны из `04_Проблемные_зоны.md`.

Способы защиты по уроку «Методы защиты данных»: **шифрование**, **обфускация** (токенизация, перемешивание, зануление, скремблирование), **маскировка** (статическая, динамическая, детерминированная, недетерминированная), **обезличивание** (для аналитики и ML).

## 2. Матрица «данные — способ защиты»

| Данные | Тег | Способ защиты | Где применяем | Обоснование |
|---|---|---|---|---|
| ФИО, ДР, телефон, email | `pii` | Шифрование at rest (AES-256), TLS 1.3 in transit | `Patients`, БД портала, API | Базовые PII, требуют защиты в покое и передаче |
| Адрес прописки, место работы/учёбы | `pii` | Исключить из сбора (Data Minimization); если остаётся — шифрование + маскировка в интерфейсе | Форма записи | Избыточные данные, приоритет — прекратить сбор |
| Хронические заболевания | `phi` | Шифрование at rest, динамическая маскировка для не-врачей | Медкарта, портал врача | Врачебная тайна, доступ только у врача |
| Медкарты (сканы, PDF, JPG) | `phi`, `pii` | Шифрование at rest (полное шифрование диска + шифрование файлов), ACL, аудит | `Patient1-FIO-BD`, объектное хранилище | Врачебная тайна + PII, критический риск |
| Результаты анализов | `phi` | Шифрование, детерминированная маскировка для аналитики | `RegistryByDate`, озеро данных | Нужна связность для BI, но без раскрытия |
| Журнал записи | `pii` | Шифрование, RBAC на уровне записей | `Journal-Doctor-FIO 1` → БД портала | Контакты и время приёма |
| Клиентские контракты | `contract`, `pii` | Шифрование, статическая маскировка в непродакшн | Ресепшен, файлы | Договоры содержат PII |
| Согласия на ПДн | `contract` | Шифрование, аудит доступа, неизменяемое хранение | Новый реестр согласий | Юридическое доказательство |
| Данные об оплате | `payment`, `pii` | Токенизация, TLS 1.3, шифрование в 1С | ККМ, 1С, платёжный шлюз | Платёжные данные — токенизация стандарт |
| ПДн сотрудников | `hr`, `pii` | Шифрование, RBAC (кадры / зарплата / отчётность), аудит | 1С Бухгалтерия | Отдельный объект защиты по 152-ФЗ |
| Данные ТМЦ | `commercial` | Шифрование, RBAC | 1С ТиС | Коммерческая тайна |
| Почтовая переписка | `pii`, `phi` | DLP, шифрование почтового канала, аудит | Exchange | Неучтённый канал ПДн |
| Данные для BI/ML | все | Обезличивание (псевдонимизация, k-анонимность), маскировка | Озеро данных | Аналитика без раскрытия PII |

## 3. Способы защиты по состояниям данных

| Состояние | Угроза | Способ | Технология |
|---|---|---|---|
| At rest | Кража носителя, несанкционированный доступ | Шифрование | AES-256, FDE, шифрование БД и файлов |
| In transit | Перехват, MITM, подслушивание | Шифрование канала | TLS 1.3, VPN, SSH |
| In use | Скрапинг памяти, инсайдер | Минимизация в памяти, TEE, аудит | TEE (по возможности), ограничение выборок, мониторинг |

## 4. Обфускация и маскировка — где применяем

| Метод | Где применяем | Пример |
|---|---|---|
| Токенизация | Платёжные данные, API-ответы | Номер карты → токен |
| Скремблирование | Тестовые среды, демо | ФИО → случайные символы |
| Зануление | Логи, отчёты без PII | Телефон → `000-000-0000` |
| Перемешивание | Обучающие наборы | Нарушение связей пациент — диагноз |
| Статическая маскировка | Передача данных подрядчикам, тест | Копия БД с фиктивными PII |
| Динамическая маскировка | Продакшн, интерфейсы | Кассир видит только последние 4 цифры |
| Детерминированная маскировка | BI, сопоставление данных | Один и тот же ID → один и тот же токен |
| Недетерминированная маскировка | Исследовательские наборы | Максимальная защита, связи нарушены |

## 5. Data Minimization — что сокращаем

| Данные | Решение |
|---|---|
| Адрес прописки | Исключить из формы |
| Место работы/учёбы | Исключить из формы |
| Хронические заболевания | Оставить, но ограничить доступ врачом |
| Сканы документов личности | Хранить ограниченное время, только для договора |

## 6. Выводы

- Для всех PII и PHI обязательно шифрование at rest и TLS 1.3 in transit.
- Платёжные данные — токенизация, а не только шифрование.
- Для BI/ML — обезличивание и маскировка, иначе озеро данных станет новым источником утечки.
- Расширенная форма подлежит сокращению (Data Minimization).
- Механизм тегирования (файл `06`) связывает категорию данных со способом защиты автоматически.
