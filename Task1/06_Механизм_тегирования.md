# Механизм тегирования конфиденциальных данных

## 1. Назначение

Документ описывает механизм тегирования данных в «Медикаменте»: таксономию тегов, 
правила присвоения, связь с управлением доступом и автоматизацией защиты. 
Опирается на урок «Управление данными и тегирование» и классификацию из `01`.

## 2. Таксономия тегов

| Тег | Категория | Примеры данных | Базовый уровень доступа |
|---|---|---|---|
| `pii` | Персональные данные | ФИО, ДР, телефон, email, адрес | Ресепшен, врач, бухгалтер (ограниченно) |
| `phi` | Медицинские данные | Диагноз, хроники, анализы, назначения | Только врач |
| `payment` | Платёжные данные | Суммы, реквизиты, чеки | Кассир, бухгалтер |
| `contract` | Договорные данные | Контракты, согласия | Ресепшен, юрист |
| `hr` | ПДн сотрудников | Кадры, зарплата, табели | Бухгалтер, руководитель |
| `commercial` | Коммерческая тайна | ТМЦ, закупки, поставщики | Склад, бухгалтер |

Комбинированные теги: `pii+phi` (медкарта), `contract+pii` (договор), `hr+pii` (кадры).

## 3. Правила присвоения тегов

1. **На уровне поля** — каждое поле в схеме БД имеет тег (например, `patients.full_name` → `pii`).
2. **На уровне таблицы** — тег наследуется от максимально чувствительного поля.
3. **На уровне файла** — метаданные файла (PDF, JPG) содержат теги при загрузке.
4. **На уровне API-контракта** — каждое поле в OpenAPI-схеме помечено тегом; 
5. без тега контракт не проходит валидацию.
5. **На уровне потока** — DFD-стрелки несут теги (уже отражено в `02`).

## 4. Связь тегов с доступом (RBAC/ABAC)

| Тег | RBAC-роль | ABAC-атрибут |
|---|---|---|
| `pii` | reception, doctor, accountant | Атрибут `department`, `purpose` |
| `phi` | doctor | Атрибут `medical_license`, `patient_consent` |
| `payment` | cashier, accountant | Атрибут `financial_role` |
| `contract` | reception, lawyer | Атрибут `contract_access` |
| `hr` | accountant, hr_manager | Атрибут `hr_role` |
| `commercial` | warehouse, accountant | Атрибут `procurement_role` |

Правило: доступ разрешён, если роль пользователя входит в список для тега **и** 
выполнены ABAC-атрибуты (контекст: цель, отделение, согласие пациента).

## 5. Автоматизация по тегам

| Событие | Действие по тегу |
|---|---|
| Создание записи с `pii` | Автоматическое шифрование поля |
| Запись с `phi` | Ограничение доступа только врачам, аудит чтения |
| Данные с `payment` | Токенизация перед сохранением |
| Данные с `hr` | Отдельная схема БД, отдельные роли |
| Данные без тега в продакшне | Блокировка записи, алерт |
| Данные с `pii` старше срока хранения | Автоматическое удаление / обезличивание |
| Выгрузка в озеро данных | Обязательное обезличивание для `pii` и `phi` |

## 6. Инструменты тегирования

С учётом стека техдира (Java, Postgres, ClickHouse, Elastic, Kubernetes, Victoria Metrics):

| Задача | Инструмент | Обоснование |
|---|---|---|
| Каталог метаданных и тегов | OpenMetadata или DataHub | Open-source, интеграция с Postgres, ClickHouse, Elastic |
| Политики доступа по тегам | Open Policy Agent (OPA) / Kyverno | Политики как код, интеграция с Kubernetes |
| Аудит доступа | Elastic | Уже в стеке, подходит для логов |
| Управление секретами и ключами | HashiCorp Vault | Шифрование, ключи, ротация |
| DLP и обнаружение PII | Open-source DLP или самописные сканеры | Поиск PII в файлах и почте |
| Data Lineage | OpenMetadata Lineage | Прослеживаемость потоков |

Примечание: коммерческие платформы (BigID, Collibra, Informatica) функционально богаче, но дороги. 
Для компании масштаба «Медикаменте» на старте достаточно open-source + OPA.

## 7. Процесс внедрения тегирования

1. Инвентаризация полей и присвоение тегов (на основе `01`).
2. Настройка каталога метаданных (OpenMetadata).
3. Написание OPA-политик по тегам.
4. Интеграция тегов в API-контракты (обязательная валидация).
5. Настройка автоматических действий (шифрование, удаление, обезличивание).
6. Обучение сотрудников правилам разметки.
7. Регулярный аудит: данные без тегов → алерт.

## 8. Выводы

- Тегирование — связующее звено между классификацией данных, доступом и автоматической защитой.
- Таксономия минимальна (6 тегов) и расширяема.
- Связка тегов с RBAC/ABAC закрывает проблемную зону 4.1 из `04`.
- Автоматизация по тегам закрывает часть требований Privacy by Design (privacy as default).
