# Инструменты, способы и меры защиты по потокам данных

## 1. Назначение

Документ сопоставляет каждый поток из сводной карты (`02_DFD_As-Is.md`, раздел 4) с конкретными мерами 
и инструментами защиты. Опирается на `05_Данные_и_способы_защиты.md` и `06_Механизм_тегирования.md`.

## 2. Меры по потокам

| Поток | Данные | Тег | Меры | Инструменты |
|---|---|---|---|---|
| Пациент → ресепшен | ФИО, ДР, телефон, email | `pii` | TLS 1.3, валидация ввода, согласие на обработку | Портал записи, OPA-политика |
| Ресепшен → журнал | Запись к врачу | `pii` | RBAC на уровне записей, шифрование at rest, аудит | Postgres + шифрование, Elastic-аудит |
| Врач → файлы | Заметки, назначения | `phi` | Шифрование файлов, ACL, аудит чтения | Объектное хранилище с шифрованием, Vault |
| Лаборатория → реестр | Результаты анализов | `phi` | API с TLS 1.3, валидация контракта, теги в схеме | API Gateway, OpenAPI + OPA |
| Сканы → диск | Медкарты | `phi`, `pii` | FDE + шифрование файлов, ACL, аудит, DLP | Объектное хранилище, DLP-сканер |
| Пациент → касса | Оплата | `payment` | TLS 1.3, токенизация | Платёжный шлюз, токенизация |
| Касса → Excel | Платёж | `payment` | Убрать Excel, оставить 1С как источник правды | 1С клиент-сервер |
| Сотрудник → 1С | Кадровые данные | `hr`, `pii` | Шифрование, RBAC (кадры/зарплата), аудит | 1С клиент-сервер, OPA |
| Поставщик → склад | Накладные | `commercial` | Шифрование, RBAC | 1С ТиС клиент-сервер |
| Лаборатория ↔ ресепшен | Направления, результаты | `phi`, `pii` | Заменить неформальный канал на API с TLS, аудит | API Gateway, интеграционная шина (NiFi) |
| Данные → BI/ML | Все | все | Обезличивание, маскировка, теги | Озеро данных, ETL с обезличиванием |
| Почта | PII, PHI | `pii`, `phi` | DLP, шифрование, аудит | Exchange + DLP, журналирование |

## 3. Меры по уровням архитектуры

| Уровень | Меры | Инструменты |
|---|---|---|
| Сеть | Сегментация, TLS, VPN | Firewall, VPN, TLS-терминация |
| Приложение | Аутентификация, авторизация, валидация | Keycloak / OPA, OWASP-практики |
| Данные | Шифрование, маскировка, обезличивание, теги | Vault, OpenMetadata, OPA |
| Хранилище | FDE, ACL, резервирование | Шифрование дисков, репликация |
| Мониторинг | Аудит, алертинг, аномалии | Elastic, Victoria Metrics |
| Процессы | Privacy by Design, Data Minimization, Lineage | Политики, обучение, аудит |

## 4. Меры по проблемным зонам (из `04`)

| Проблемная зона | Мера | Инструмент |
|---|---|---|
| 3.1. Медкарты на общем диске | Объектное хранилище с шифрованием, ACL, аудит | MinIO / S3-совместимое, Vault |
| 3.2. Нет аудита | Централизованный аудит всех действий | Elastic, Filebeat, auditd |
| 3.3. Неформальный обмен с лабораторией | API с TLS, контракт с тегами, аудит | API Gateway, OpenAPI, OPA |
| 3.4. Нет согласий | Реестр согласий, аудит | БД + OPA, портал |
| 4.1. Нет RBAC/ABAC | Политики по тегам | OPA, Keycloak |
| 4.2. Двойной учёт | Единый источник правды в 1С клиент-сервер | 1С, ETL |
| 4.3. ПДн сотрудников | Отдельный регламент, RBAC | 1С, OPA |
| 4.4. Избыточный сбор | Сократить форму | Портал, валидация |
| 4.5. Нет Data Lineage | Каталог метаданных и lineage | OpenMetadata / DataHub |
| 5.1. 1С файловый режим | Перевод в клиент-сервер | 1С, СУБД |
| 5.2. Почта | DLP, шифрование | DLP, Exchange |
| 5.3. Нет уничтожения | Процедура удаления по тегам | OPA, скрипты, аудит |
| 5.4. Нет резервирования | Бэкапы, репликация | Backup-система, реплика |

## 5. Что внедряем в первую очередь (MVP, 2 месяца)

1. Объектное хранилище с шифрованием для медкарт (закрывает 3.1).
2. Аудит действий в Elastic (закрывает 3.2).
3. Реестр согласий (закрывает 3.4).
4. OPA-политики по тегам для портала записи (закрывает 4.1).
5. API-контракт с лабораторией с TLS и тегами (закрывает 3.3).

## 6. Что во вторую очередь (год)

1. Перевод 1С в клиент-сервер (5.1).
2. Озеро данных с обезличиванием (4.5, BI/ML).
3. DLP для почты (5.2).
4. Полная процедура уничтожения ПДн (5.3).
5. Резервирование и репликация (5.4).

## 7. Выводы

- Каждый поток из DFD получает конкретную меру и инструмент, без «общих слов».
- Приоритет — закрытие критических зон (3.1–3.4) в первые 2 месяца.
- Меры согласованы со стеком техдира (Java, Postgres, ClickHouse, Elastic, Kubernetes, Victoria Metrics).
