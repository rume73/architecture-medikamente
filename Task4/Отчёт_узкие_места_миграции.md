# Отчёт: узкие места миграции и рекомендации

## 1. Введение

«Медикаменте» планирует миграцию с монолитной архитектуры (1С в файловом режиме, Excel, файловый сервер,
один физический сервер) на микросервисную (целевая архитектура из `Task2`). 
Отчёт выявляет потенциальные узкие места, которые могут снизить производительность, 
стабильность и безопасность нового решения.

Метод: диаграмма Исикавы (6 категорий) + приоритизация рекомендаций по матрице «Влияние × Вероятность».

## 2. Компоненты, затронутые миграцией

| Компонент | As-Is | To-Be | Риск миграции |
|---|---|---|---|
| База данных | 1С файловая, Excel | PostgreSQL, ClickHouse | Потеря данных, рассинхрон |
| Бизнес-логика | Монолит 1С | Микросервисы | Долг разбиения, слом зависимостей |
| Коммуникации | OLE, локальная сеть | API Gateway, TLS, mTLS | Некорректные контракты, задержки |
| Серверное оборудование | Один физический сервер | Kubernetes, облако/on-prem | Отказоустойчивость, ёмкость |
| Интеграции | ККМ (OLE), лаборатория (вручную) | API Gateway, Laboratory Service | Срыв сроков, неформальные каналы |
| Аутентификация | AD | Keycloak + OPA | Несовместимость, миграция пользователей |
| Данные PII/PHI | Файлы на шаре | Object Storage + теги | Утечка в процессе миграции |

## 3. Результаты анализа (по диаграмме Исикавы)

- **Инфраструктура:** SPOF (единый сервер), файловый режим 1С, отсутствие бэкапов, задержки филиалов.
- **ПО:** монолит, OLE, Excel, отсутствие API и аудита.
- **Данные:** дублирование, нет источника правды, сканы, нет Lineage, смешение PII/PHI.
- **Интеграция:** неформальный обмен с лабораторией, ККМ, нет API Gateway, Exchange.
- **Персонал:** сопротивление, нет опыта микросервисов, малая команда, нет обучения.
- **Процессы:** ручная запись, двойной учёт, нет согласий, нет удаления, нет мониторинга.

## 4. Рекомендации и приоритизация

|---|---|---|---|---|---|

## 5. План миграции по этапам

### Этап 0. Подготовка (до миграции)
- P1: резервное копирование, перевод 1С в клиент-сервер, API-контракты, SPOF.
- Обучение команды основам Kubernetes и OPA.
- Инвентаризация неформальных каналов (мессенджеры).

### Этап 1. MVP (2 месяца)
- API Gateway, IAM, Consent Service, Audit Service.
- Замена обмена с лабораторией на API.
- Портал записи (клиент + ресепшен).
- Перенос медкарт в объектное хранилище с тегами.

### Этап 2. Основная миграция (6–9 месяцев)
- Домены: Appointment, Medical Records, Billing, Inventory, HR.
- Data Lake с Privacy Layer.
- Перевод 1С и ККМ на API.

### Этап 3. Стабилизация (год)
- Мониторинг, алертинг, Data Lineage.
- Автоматизированный контроль (Task3).
- Масштабирование под филиалы.

## 6. Выводы

- Главные узкие места — инфраструктура (SPOF, файловая 1С) и отсутствие API-контрактов. Их надо закрывать до миграции.
- Без Data Lineage и тегирования миграция данных PII/PHI создаст риск утечки.
- Персонал и процессы — не менее важны, чем технологии: без обучения и вовлечения команды миграция затянется.
- Приоритет P1 (5 мер) закрывает 80% рисков падения производительности.
- Отчёт согласован с Task1–Task3: рекомендации опираются на проблемные зоны, целевую архитектуру и средства защиты.
