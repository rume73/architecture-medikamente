# Сводная таблица защиты данных

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| Медкарты (сканы, PDF, JPG) | Врачебная тайна (323-ФЗ) и персональные данные (152-ФЗ). Утечка грозит уголовной ответственностью и потерей репутации. | Объектное шифрование (SSE-KMS), шифрование дисков (FDE), разграничение прав (ACL), аудит доступа, DLP |
| Диагнозы, хроники, назначения | Врачебная тайна. Несанкционированный доступ или изменение могут навредить здоровью пациента. | Шифрование базы данных (TDE / AES-256), RBAC/ABAC, динамическая маскировка в интерфейсах, аудит |
| Результаты анализов | Врачебная тайна и целостность данных. Изменение результатов приведёт к ошибкам в лечении. | Шифрование БД (TDE), шифрование канала (TLS 1.3), контроль целостности (хеширование), аудит |
| Согласия на обработку ПДн | Юридическое основание обработки (152-ФЗ). Без согласия обработка данных незаконна. | Шифрование, неизменяемое хранение (WORM), строгий аудит доступа |
| ФИО, дата рождения, телефон, email | Базовые персональные данные (152-ФЗ). Риск утечки и мошенничества. | Шифрование БД (AES-256), TLS 1.3, RBAC/ABAC (OPA), маскировка при отображении |
| Адрес, место работы, учёба | Избыточные PII (нарушение Data Minimization). При утечке повышают риск социальной инженерии. | Исключить из сбора; при необходимости хранения — шифрование |
| Клиентские контракты | Содержат PII и коммерческие условия (152-ФЗ). | Шифрование файлов и БД, ACL, аудит |
| Данные об оплате и чеки | Финансовые данные, банковская тайна. Риск мошенничества. | Токенизация, TLS 1.3, шифрование в 1С |
| ПДн сотрудников (кадры, зарплата) | Персональные данные сотрудников (152-ФЗ). Риск внутреннего мошенничества. | Шифрование БД (TDE), RBAC (разделение ролей), аудит доступа |
| Почтовая переписка | Может содержать PII и медицинские данные (152-ФЗ). Неучтённый канал утечки. | Шифрование почтового канала (TLS), DLP-система, шифрование ящиков, аудит |
| Журнал записи к врачу | Содержит PII (кто, когда и к кому записан). | Шифрование БД (TDE), RBAC, аудит |
| Данные ТМЦ и закупок | Коммерческая тайна. Риск финансовых потерь. | Шифрование БД (TDE), RBAC, TLS 1.3 |
| Ключи шифрования и секреты | Основа всей системы защиты. Компрометация обнуляет защиту. | HSM (аппаратный модуль), HashiCorp Vault, ротация ключей, mTLS |
| Логи системы и метаданные | Нужны для расследования инцидентов. Их изменение скрывает следы атак. | Шифрование, контроль целостности (хеши), доступ по ролям |

## Пояснение к классификации

Все данные в таблице классифицированы по четырём уровням чувствительности:
1. **Особо чувствительные** — медкарты, диагнозы, анализы, согласия (требуют защиты во всех состояниях).
2. **Конфиденциальные** — PII, платежи, контракты, ПДн сотрудников, почта.
3. **Внутренние** — журналы, ТМЦ, метаданные, логи.
4. **Аппаратные и системные** — ключи шифрования (защищаются на уровне оборудования).

Подробная методология, разбор трёх состояний данных (at rest, in transit, in use) и описание инструментов 
находятся в файлах `01_Классификация_данных.md`, `02_Инструменты_защиты.md`, `03_Автоматизированный_контроль.md`
и `04_Реестр_средств_защиты.md`.
