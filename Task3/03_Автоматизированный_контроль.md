# Автоматизированный контроль защиты данных

## 1. Назначение

Документ описывает средства автоматизации контроля за данными.
Задача — сделать защиту самодействующей, а не ручной: политики, аудит, алертинг, сканирование, ротация.
Опирается на принцип PbD «proactive not reactive» из `Task2/01`.

## 2. Уровни автоматизации

| Уровень | Что автоматизируется | Инструмент |
|---|---|---|
| Политики доступа | Проверка ролей и тегов при каждом запросе | OPA / Kyverno |
| Тегирование | Присвоение тегов при записи, блокировка без тега | OpenMetadata + сервис тегирования |
| Шифрование | Автоматическое шифрование по тегу | Vault + TDE |
| Маскировка | Динамическая по роли и контексту | API Gateway + OPA |
| Обезличивание | При выгрузке в аналитику | Privacy Layer |
| Аудит | Журналирование всех обращений | Elastic, auditd |
| Алертинг | Аномалии, массовые выгрузки, доступ вне часов | Elastic + Victoria Metrics |
| Ротация ключей | По расписанию | Vault |
| Сканирование PII | Поиск нетегированных PII в файлах и почте | DLP |
| Удаление по запросу | Каскадное удаление во всех системах | Consent Service + Data Lineage |

## 3. Автоматизированные контроли по состояниям

### 3.1. At rest
- Автоматическое шифрование новых таблиц/файлов по тегу.
- Ночное сканирование: есть ли данные с `pii`/`phi` без шифрования → алерт.
- Ротация ключей по расписанию (Vault).
- Проверка ACL: есть ли избыточные права → отчёт.

### 3.2. In transit
- Автоматическая проверка TLS-версии на всех endpoint.
- Отключение устаревших протоколов (TLS 1.0/1.1).
- Мониторинг сертификатов: срок истечения → алерт за 30 дней.
- mTLS между сервисами в Kubernetes — обязателен, иначе под не запускается.

### 3.3. In use
- OPA-политики: default deny для тегированных данных.
- Динамическая маскировка в интерфейсах по роли.
- Аудит каждого чтения тегированных полей.
- Алерт при массовой выборке (например, >100 записей за минуту).
- Алерт при доступе вне рабочих часов.

## 4. Средства мониторинга

| Средство | Что мониторит | Реакция |
|---|---|---|
| Elastic | Логи доступа, изменения | Дашборды, поиск инцидентов |
| Victoria Metrics | Метрики сервисов | Алерты по порогам |
| OPA | Решения о доступе | Логи решений, отказ → событие |
| Vault Audit | Доступ к ключам и секретам | Алерт при аномалиях |
| DLP | Утечки через почту, USB, выгрузки | Блокировка + алерт |
| OpenMetadata | Теги и lineage | Алерт: данные без тега |
| SIEM (Elastic Security) | Корреляция событий | Инциденты, оповещения |

## 5. Правила алертинга (примеры)

| Правило | Условие | Действие |
|---|---|---|
| Массовая выгрузка | >100 записей с `pii` за 1 мин | Блокировка, алерт безопаснику |
| Доступ вне часов | Обращение к `phi` с 22:00 до 07:00 | Алерт, запрос подтверждения |
| Нетегированные PII | Найдены `pii` без тега | Блокировка записи, алерт |
| Избыточные права | Роль имеет доступ к `phi` без медицинской лицензии | Отзыв прав, отчёт |
| Истечение сертификата | <30 дней | Задача на продление |
| Отказ OPA | Массовые отказы в доступе | Проверка: атака или ошибка политики |
| Изменение тега | Кто-то снял тег `phi` | Блокировка, аудит |

## 6. Регулярные автоматизированные проверки

| Проверка | Частота | Инструмент |
|---|---|---|
| Сканирование PII в файлах и почте | Ежедневно | DLP |
| Проверка шифрования БД и хранилищ | Еженедельно | Скрипты + Vault |
| Аудит прав доступа | Ежемесячно | OPA + отчёты |
| Ротация ключей | По расписанию (90 дней) | Vault |
| Тест восстановления из бэкапа | Ежеквартально | Backup-система |
| Проверка Data Lineage | Ежемесячно | OpenMetadata |

## 7. Выводы

- Автоматизация делает защиту непрерывной: политики, аудит, алертинг работают без ручного вмешательства.
- Каждый класс данных и состояние покрыты автоматизированными контролями.
- Алертинг настроен на конкретные правила, а не «на всё подряд» — иначе будет шум.
